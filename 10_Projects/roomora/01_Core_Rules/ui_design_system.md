# UI/UX Design System & Frontend Manual — Roomora

> **배경**: 아무런 UI/UX 기준 없이 기능 구현만 지시하면 에이전트는 "딱 기능만 돌아가는 촌스러운 템플릿 화면"을 만든다. 모든 프론트엔드 작업은 아래 4대 원칙과 검수 기준을 준수해야 한다.

---

## 1. '왜(Why)' · 맥락(Context) · 정보 구조(IA)
1. **감정과 상황 먼저 정의**: *"버튼을 누른다"*가 아니라 *"예산이 빠듯한 세입자가 불안한 마음으로 조건에 맞는 방을 찾는다"*처럼 직전·직후 맥락을 기준으로 화면을 배치한다.
2. **화면별 단일 목적 (Primary Action)**: 한 화면에 모든 기능을 때려 넣지 않고 **1순위 핵심 행동(Primary Action)** 1개만 가장 먼저 눈에 띄게 강조하고, 부차적 요소는 덜어낸다.
3. **비즈니스 지표 연결**: 첫 화면 이탈률 감소(빠른 조건 칩), 전환율 극대화(검색 → 체크리스트 담기 1클릭), 리텐션(체크리스트 진행률 · 주간 콘테스트).

---

## 2. 디테일의 완성: 4대 상태 · 폼 UX · 마이크로 인터랙션

### 4대 화면 상태 필수 설계
1. **Empty State**: 데이터가 0건일 때 빈 화면 방치 금지 → 안내 문구 + 다음 행동 유도(CTA) 버튼 제공
2. **Loading State (Skeleton UI)**: API 대기 중 빈 박스 대신 `animate-pulse` 스켈레톤 UI 표시
3. **Error State**: 네트워크/서버 오류 시 사용자 친화적 안내 + **`[다시 시도]`** 버튼 제공
4. **Overflow 방어**: 예상보다 긴 제목·품목명·메모에 `line-clamp-1`, `line-clamp-2`, `break-words`, `min-w-0` 적용

### 폼 검증 · 중복 클릭 방지 · 피드백 통일
- **입력 검증 시점**: 필드 이탈(`onBlur`) 및 제출(`onSubmit`) 시 인라인 에러 표시 (브라우저 기본 `alert()` / `confirm()` 절대 금지)
- **중복 클릭 방지**: API 요청 중 버튼 `disabled` + 로딩 텍스트/스피너 전환
- **알림 vs 확인 분리**: 사소한 완료 알림은 **Toast**, 삭제·탈퇴 등 파괴적 행동 전에는 **Confirm Modal** 표시
- **버튼 5대 상태**: `Default` / `Hover` / `Pressed(active:scale-[0.98])` / `Disabled` / `Focus(focus-visible:ring-2)` 모두 정의

## 3. 디자인 토큰 · 금지 목록(Anti-Pattern) · UX Writing

### 레퍼런스 & 디자인 토큰 고정
- **무드**: 오늘의집의 밝은 사진 중심 여백 + 29CM/핀터레스트의 절제된 에디토리얼 타이포그래피
- **4px/8px 그리드 & Radius**: 간격은 4px 배수(`gap-2`, `gap-4`, `gap-6`, `gap-8`, `p-6`, `p-8`), 모서리는 위계에 따라 `rounded-xl`(입력/버튼), `rounded-2xl`(카드), `rounded-3xl`(히어로/섹션)로 통일
- **타이포그래피 (`Pretendard`)**: H1(`text-2xl md:text-4xl font-bold`), H2(`text-lg md:text-xl font-bold`), Body(`text-sm md:text-base`), Caption(`text-xs text-zinc-500`)
- **시맨틱 컬러**:
  - 배경 `#FAF9F6` / 카드 `#FFFFFF` / 텍스트 `#18181B` / 보조 `#71717A` / 보더 `#E4E4E7`
  - Primary `#18181B` / Accent `#8C583A` / Success `#15803D` / Warning `#B45309` / Danger `#DC2626`

### 금지 목록 (Forbidden Anti-Patterns — AI 티 제거)
1. **과한 네온/원색 그라데이션** (`from-amber-50 to-orange-50` 등) 남발 금지
2. **카드 안의 카드 중첩 (Card-in-Card)** 금지 — 경계선이 겹쳐 답답해 보이므로 배경 대비(`#FAF9F6`)나 여백으로 구분
3. **제목마다 붙이는 이모지 아이콘** 금지 — 필요 시 단일 아이콘 세트 또는 깔끔한 텍스트만 사용
4. **요청하지 않은 가짜 통계/장식 배지** 삽입 금지 (카드 1장당 `사진 + 제목 + 핵심 조건 1줄` 밀도 유지)

### UX Writing (기계적·개발자 용어 금지)
| 금지 표현 | 권장 표현 (다음 행동 안내) |
| :--- | :--- |
| AI RAG 통합 검색 / Citations / 1-Click | **내 조건으로 공간 찾기** / **비슷한 조건의 실제 방 사례** / **내 체크리스트로 담기** |
| 오류 코드 404 / 요청 실패 | **페이지를 찾을 수 없어요. 홈으로 이동할까요?** / **잠시 후 다시 시도해 주세요.** |
| 확인 / 취소 / 입력하세요 | **저장하기 / 돌아가기 / 예산(원)을 입력해 주세요** |

## 4. 반응형 레이아웃 & 구현 후 브라우저 검증
- **반응형 규칙**: 최대 컨텐츠 폭 `max-w-6xl`(1152px), 모바일(`375px`) 기준에서는 1열 그리드(`grid-cols-1`), 내비게이션 축약 및 가로 스크롤/잘림 방지
- **시각 검증(DoD)**: 코드 작성 후 데스크톱과 모바일(`375px`) 뷰포트에서 직접 렌더링을 확인해 콘솔 에러 및 레이아웃 깨짐이 없음을 검증한다.

## 5. 최종 검수 체크리스트 (표면적인 UI vs 깊이 있는 UI/UX)
- [ ] **기획**: 예쁜 화면부터 그리지 않고 사용자 여정과 화면별 단일 목적(Primary Action)을 먼저 잡았는가?
- [ ] **시각 규칙**: 디자인 토큰(색상/8px 그리드/폰트)과 금지 목록(Card-in-Card, 이모지 남발 금지)을 지켰는가?
- [ ] **상태 관리**: Empty / Skeleton / Error(+재시도) / Overflow / 중복 클릭 방지가 모두 구현되었는가?
- [ ] **텍스트**: 기계적 문구 대신 사용자의 다음 행동을 유도하는 UX Writing인가?
- [ ] **수정 기준**: *"더 예뻐 보여서"*가 아니라 *"사용자가 3초 안에 핵심 버튼을 찾고 망설이지 않게 하기 위해"* 수정했는가?
