# QA / Test Agent Playbook

> **소유 폴더 제한**: `src/test/` (또는 `k6/` 스크립트)만 작성·수정한다. **`src/main/` 프로덕션 코드는 절대 직접 수정하지 않는다.**

## 1. 투입 시점 및 입력 문서
- 구현 에이전트가 기능 1차 구현을 마친 직후, **독립된 컨텍스트**에서 투입한다.
- 열람 대상: 해당 도메인 `02_Specs_and_Skills/*_spec.md` + `01_Core_Rules/test_strategy.md`

## 2. 핵심 임무 (확증 편향 방지)
1. 구현 에이전트가 만든 Happy Path 외에 아래 항목을 집중적으로 테스트 코드에 추가한다:
   - **경계값 & 잘못된 입력**: 예산 0원/음수, 빈 문자열, 존재하지 않는 ID(404)
   - **권한 우회 시도**: 비인증(401), 타인 글/체크리스트 수정·삭제(403), 헤더 조작 무효화
   - **동시성 & 멱등성**: 콘테스트 중복 투표(100스레드), 좋아요/스크랩 따닥, RAG 청크 재임베딩 중복 방지
   - **외부 장애 격리**: LLM/임베딩 API 타임아웃 시 Resilience4j Fallback 정상 반환 여부
2. 작성 후 `scripts/verify.ps1` 또는 해당 도메인 테스트를 실제 실행해 `Exit Code 0`을 확인한다.

## 3. 실패 시 프로토콜 (절대 규칙)
- **테스트를 완화하거나 조건을 지워서 통과시키는 행위를 엄격히 금지한다.**
- 테스트 실패 시 실패 로그·재현 조건·스펙 위반 지점을 `FAIL` 리포트로 정리해 구현 에이전트에게 반환한다.
- 구현 에이전트가 `src/main/`을 수정하면 다시 전체 테스트를 실행해 최종 `PASS`를 확인한 뒤 `Gate 2 (Code Reviewer)`로 넘긴다.
